# ข้อความขอความยินยอม (PDPA) — ยืนยันตัวตนด้วย ThaID

> **ร่าง v0.1 — ยังไม่มีผลบังคับใช้**
> ต้องให้ DPO และที่ปรึกษากฎหมายของพรรคตรวจและรับรอง ก่อนนำไปแสดงบนหน้าสมัคร
> ช่องที่เป็น `[...]` = เติมข้อมูลทางการของพรรค
>
> `version` ปัจจุบัน = **`2026-09-v1`** — ต้องตรงกับ `DEFAULT_CONSENT_VERSION` ใน
> `server/verify/integration/verify-prefill-client.ts` **bump ทุกครั้งที่แก้ข้อความในหมวด A หรือ B**

## A. ข้อความบนช่องติ๊กยินยอม (บังคับติ๊กก่อนกดปุ่ม "ยืนยันตัวตนด้วย ThaID")

แสดงแยกจากข้อความอื่นบนฟอร์ม เป็นการกระทำเชิงบวก (ไม่ติ๊กไว้ล่วงหน้า):

> ☐ ข้าพเจ้า **ยินยอมโดยชัดแจ้ง** ให้พรรคไทยก้าวใหม่ ประมวลผลข้อมูลส่วนบุคคลของข้าพเจ้า
> ซึ่งรวมถึง **ข้อมูลการเป็นสมาชิกพรรคการเมือง (ข้อมูลอ่อนไหว)** และ **เลขประจำตัวประชาชน**
> เพื่อ **ยืนยันตัวตนและตรวจสอบความถูกต้องของข้อมูลกับกรมการปกครองผ่านระบบ ThaID**
> ตามที่ระบุใน [ประกาศการคุ้มครองข้อมูลส่วนบุคคลสำหรับการยืนยันตัวตน]([ลิงก์]) —
> ข้าพเจ้าทราบว่าการยืนยันตัวตนนี้เป็นทางเลือก และสามารถถอนความยินยอมได้ภายหลัง

**ข้อกำหนดการแสดงผล**
- ปุ่มกดไม่ได้จนกว่า: กรอกเลขบัตร 13 หลักที่ผ่าน checksum **และ** ติ๊กช่องนี้
- ลิงก์ "ประกาศการคุ้มครองข้อมูลส่วนบุคคล..." เปิดข้อความในหมวด B (แท็บใหม่หรือ modal)
- ไม่ผูกการยินยอมนี้กับการยินยอมเรื่องอื่น (เช่น รับข่าวสาร) — ต้องเป็นช่องแยก

## B. ประกาศการคุ้มครองข้อมูลส่วนบุคคล — การยืนยันตัวตนผู้สมัครสมาชิกด้วย ThaID

*(ข้อความเต็ม สำหรับหน้า/ป๊อปอัป "อ่านเพิ่มเติม" — ครอบคลุมรายการแจ้งตาม ม.23)*

**1. ผู้ควบคุมข้อมูลส่วนบุคคล**
พรรคไทยก้าวใหม่ สำนักงานใหญ่ `[ที่อยู่]` — ติดต่อเรื่องข้อมูลส่วนบุคคล:
เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) `[อีเมล]` โทร `[เบอร์]`

**2. ข้อมูลที่เก็บรวบรวมและใช้เพื่อการนี้**
- การสมัคร/เป็นสมาชิกพรรคการเมือง (ข้อมูลอ่อนไหวตามมาตรา 26)
- เลขประจำตัวประชาชน 13 หลัก, ชื่อ–สกุล, วันเดือนปีเกิด, ที่อยู่ตามทะเบียนบ้าน —
  เพื่อ **เทียบ** กับฐานกรมการปกครองเท่านั้น
- ผลการเทียบ (ตรง/ไม่ตรง แต่ละรายการ), ระดับความเชื่อมั่นตัวตน, รหัสอ้างอิงธุรกรรม,
  วันเวลาที่ยืนยัน, หมายเลข IP, เวอร์ชันและเวลาที่ให้ความยินยอม

**3. วัตถุประสงค์**
ยืนยันว่าผู้สมัครเป็นบุคคลจริง มีสัญชาติไทย และข้อมูลที่แจ้งตรงกับทะเบียนราษฎร
เพื่อความถูกต้องของบัญชีสมาชิกพรรค (ซึ่งมีผลตามกฎหมายพรรคการเมืองและการเลือกตั้ง)
และลดภาระการตรวจเอกสารด้วยมือ

**4. ฐานทางกฎหมาย**
ความยินยอมโดยชัดแจ้ง (มาตรา 26 ประกอบมาตรา 19) สำหรับข้อมูลอ่อนไหวและเลขประจำตัวประชาชน;
การเก็บบันทึกผลไว้ภายในพรรคอาศัยมาตรา 26(3) (กิจกรรมขององค์กรที่มีวัตถุประสงค์ทางการเมือง
ที่กระทำต่อสมาชิกและไม่เปิดเผยออกภายนอก)

**5. สิ่งที่พรรคเก็บและไม่เก็บ**
- **ไม่เก็บ** เลขประจำตัวประชาชนของท่าน (เก็บเพียงค่าที่ผ่านการแฮชทางเดียว เพื่อกันการสมัครซ้ำ),
  **ไม่เก็บ** สำเนาบัตรประชาชน ภาพถ่าย หรือข้อมูลชีวมิติ
- ข้อมูลที่ใช้เทียบจะถูกเข้ารหัสระหว่างดำเนินการ และลบทันทีเมื่อเสร็จสิ้น
- พรรคเก็บเพียง **ผลการยืนยัน (ผ่าน/ไม่ผ่าน)** ไว้กับใบสมัครของท่าน

**6. การเปิดเผย**
ใช้ **ภายในพรรคเท่านั้น** สำหรับเจ้าหน้าที่ที่ตรวจใบสมัคร ไม่มีการเปิดเผยต่อบุคคลภายนอก
ไม่มีการส่งข้อมูลออกนอกราชอาณาจักร การเชื่อมต่อ ThaID เป็นการที่ **ท่าน** อนุญาตให้
กรมการปกครองเปิดเผยข้อมูลผ่านแอป ThaID ในแต่ละครั้ง

**7. ระยะเวลาเก็บรักษา**
ผลการยืนยันเก็บไว้ตราบที่ท่านยังเป็นสมาชิก และ `[X]` ปีหลังพ้นสภาพสมาชิก
เพื่อการตรวจสอบและระงับข้อพิพาท จากนั้นจะลบหรือทำให้ไม่สามารถระบุตัวท่านได้
ข้อมูลชั่วคราวระหว่างยืนยัน (ไม่กี่นาที) จะถูกลบโดยอัตโนมัติ

**8. สิทธิของท่าน**
ท่านมีสิทธิเข้าถึง ขอสำเนา ขอแก้ไข ขอลบ คัดค้าน ระงับการใช้ และถอนความยินยอม
รวมถึงร้องเรียนต่อสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล
ติดต่อใช้สิทธิผ่าน DPO ตามข้อ 1

**9. ผลของการไม่ให้ / การถอนความยินยอม**
การยืนยันตัวตนด้วย ThaID เป็น **ทางเลือก** — หากไม่ให้ความยินยอม ท่าน **ยังสมัครสมาชิกได้ตามปกติ**
โดยเจ้าหน้าที่จะตรวจสอบเอกสารด้วยวิธีปกติ ซึ่งอาจใช้เวลานานกว่า

## C. การถอนความยินยอม

- ถอนได้ทุกเมื่อ โดยแจ้ง DPO ตามช่องทางในข้อ 1
- การถอนความยินยอม **ไม่กระทบ** ความชอบด้วยกฎหมายของการประมวลผลที่ทำไปแล้วก่อนถอน
- เมื่อถอน: พรรคจะลบผลการยืนยันที่ผูกกับใบสมัครของท่าน (เว้นแต่มีหน้าที่ตามกฎหมายให้เก็บ)
  และกลับไปใช้การตรวจเอกสารด้วยวิธีปกติ
- **ผลต่อสมาชิกภาพ:** การถอนความยินยอมเรื่อง *การยืนยันตัวตน* ไม่ทำให้สมาชิกภาพสิ้นสุด
  แต่ `[ให้ DPO/นายทะเบียนพรรคยืนยันข้อความนี้ตามข้อบังคับพรรค]`

## หมายเหตุการนำไปใช้ (สำหรับ dev)

- ข้อความหมวด A → ใส่ใน `ThaidVerifyButton` (ดูตัวอย่างใน [`README.md`](./README.md) หัวข้อ "ก้อน C")
  แทน placeholder เดิม; ลิงก์ชี้ไปหน้าที่แสดงหมวด B
- SPA ส่งเฉพาะ `consent: { version: "2026-09-v1" }` ไปที่ `POST /api/verify/start` —
  **ห้ามส่ง `acceptedAt` จาก client**; api ประทับเวลา server เอง (ดู `integration/verify-api-routes.ts`)
- api ควร **ปฏิเสธ** คำขอที่ไม่มี `consent.version` หรือ version ไม่อยู่ในตารางหมวด D
  (ปัจจุบันยังรับผ่าน — ดู `GO-LIVE.md` ข้อ 3)
- `consent_version` / `consent_at` ถูกบันทึกลง `register_verification` ตลอดสาย (broker → ingest)
