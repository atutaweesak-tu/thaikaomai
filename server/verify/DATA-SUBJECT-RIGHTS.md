# ขั้นตอนการใช้สิทธิของเจ้าของข้อมูลส่วนบุคคล (มาตรา 30–34)
## ระบบยืนยันตัวตนผู้สมัครสมาชิกพรรคด้วย ThaID (KYC broker)

> **ร่าง v0.1 — ยังไม่มีผลบังคับใช้**
> ต้องให้เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) และที่ปรึกษากฎหมายของพรรคตรวจสอบและรับรอง
> ก่อนนำระบบขึ้นใช้จริง (`VERIFY_ENABLED=true`, `VERIFY_DRIVER=oidc`)
>
> ช่องที่เป็น `[...]` = ต้องเติมข้อมูลทางการของพรรค
> อ้างอิง: [`DPIA.md`](./DPIA.md) ข้อ 7 (สิทธิของเจ้าของข้อมูล) และ R7 — เอกสารนี้แปลงตารางสรุป
> ใน DPIA ให้เป็นขั้นตอนปฏิบัติจริง; ปิด checkbox ที่เกี่ยวข้องใน [`GO-LIVE.md`](./GO-LIVE.md) ข้อ 3

## 2. การพิสูจน์ตัวตนผู้ร้องขอสิทธิ

ระบบนี้ **ไม่เก็บเลขบัตรประชาชน 13 หลักในรูปแบบ plaintext** (เก็บเฉพาะ `id_card_hash` —
ดู [`DPIA.md`](./DPIA.md) ข้อ 2.2) การค้นบันทึกและพิสูจน์ตัวตนผู้ร้องขอจึงทำดังนี้:

1. ผู้ร้องขอแจ้งเลขบัตรประชาชน 13 หลักของตนเองในคำขอ (ใช้คำนวณ `id_card_hash` เทียบค้นหา
   บันทึกในระบบ เท่านั้น — เลขที่แจ้งมาไม่ถูกเก็บถาวรเกินความจำเป็นสำหรับขั้นตอนนี้)
2. เทียบข้อมูลประกอบอีกอย่างน้อย 1 รายการกับใบสมัครเดิม (ชื่อ–สกุล หรือวันเดือนปีเกิด
   ที่แจ้งไว้ตอนสมัคร) เพื่อกันการแอบอ้าง
3. หากผู้ร้องขอเป็นสมาชิกที่มีบัญชี login เข้าระบบสมาชิกได้ ให้ยืนยันผ่าน session
   login แทนข้อ 1–2 (ปลอดภัยกว่า) `[ยืนยันว่าระบบสมาชิกปัจจุบันรองรับหรือไม่]`
4. กรณีพิสูจน์ตัวตนไม่ได้ชัดเจน — ปฏิเสธคำขอชั่วคราวและแจ้งวิธีการยืนยันตัวตนเพิ่มเติม
   (ไม่ปฏิเสธเฉย ๆ โดยไม่ให้แนวทาง)

## 4. ขั้นตอนปฏิบัติตามประเภทสิทธิ

| สิทธิ | ขั้นตอนปฏิบัติจริง | ผู้รับผิดชอบ | ข้อจำกัด/หมายเหตุ |
|---|---|---|---|
| เข้าถึง/ขอสำเนา | ค้นหาด้วย `id_card_hash` หรือเลขที่ใบสมัคร (`register_log_id`) ใน `register_verification` → สรุปเป็นเอกสาร: ผลยืนยัน (ผ่าน/ไม่ผ่าน แต่ละรายการ), วันเวลา, เวอร์ชัน/เวลาความยินยอม → ส่งให้ผู้ร้องขอ | DPO | ระบบ KYC ไม่เก็บ PID/ชื่อ/ที่อยู่ไว้ จึงไม่มีข้อมูลอื่นให้เปิดเผยนอกจากผลยืนยัน |
| แก้ไขให้ถูกต้อง | หากผลไม่ตรง (mismatch) เกิดจากข้อมูลที่แจ้งผิด → แนะนำให้ยืนยันใหม่ผ่าน ThaID อีกครั้ง หรือส่งเอกสารให้เจ้าหน้าที่ตรวจแทน | เจ้าหน้าที่ตรวจใบสมัคร | ผล KYC เป็นผลเปรียบเทียบอัตโนมัติ ไม่มีการ "แก้ไข" ค่าโดยตรง |
| ลบ/ทำลาย | DPO สั่งการให้ผู้ดูแลระบบลบแถวใน `register_verification` ที่ตรงกับ `id_card_hash`/`register_log_id` | DPO + ผู้ดูแลระบบ | เว้นแต่มีหน้าที่ตามกฎหมายพรรคการเมือง/การเลือกตั้งให้ต้องเก็บไว้ — ให้ที่ปรึกษากฎหมายยืนยันเป็นกรณีไป โดยเฉพาะสมาชิกที่ยัง active |
| คัดค้าน/ระงับการใช้ | ตั้งค่าใบสมัครนั้นให้ไม่ใช้ผล KYC อัตโนมัติ → เจ้าหน้าที่ตรวจเอกสารด้วยมือแทน | เจ้าหน้าที่ตรวจใบสมัคร | ไม่กระทบสถานะสมาชิกภาพ |
| ถอนความยินยอม | ดำเนินการตาม [`CONSENT.md`](./CONSENT.md) หมวด C | DPO | ทำได้ทุกเมื่อ ไม่กระทบความชอบด้วยกฎหมายของการประมวลผลก่อนถอน |
| โอนย้ายข้อมูล (data portability) | แจ้งผู้ร้องขอว่าไม่เกี่ยวข้องในทางปฏิบัติ เนื่องจากระบบเก็บเพียง flag ผลยืนยันและ hash ไม่มีข้อมูลที่มีความหมายให้ส่งออก | DPO | — |

## 5. บันทึกคำขอ (Request Log)

ทุกคำขอต้องบันทึกแยกไว้ (นอกระบบ `server/verify` — DPO เป็นผู้ดูแล) เพื่อการตรวจสอบย้อนหลัง
และควบคุมให้ตอบภายในกำหนดข้อ 3:

| ฟิลด์ | รายละเอียด |
|---|---|
| วันที่/เวลาได้รับคำขอ | |
| ช่องทางที่รับคำขอ | |
| สิทธิที่ขอใช้ | |
| ผลการพิสูจน์ตัวตนผู้ร้องขอ | ผ่าน/ไม่ผ่าน + วิธีที่ใช้ |
| วันที่ตอบรับ (acknowledge) | |
| วันที่ดำเนินการเสร็จ/แจ้งผล | |
| ผู้รับผิดชอบดำเนินการ | |
| ผลลัพธ์ | ดำเนินการให้ / ปฏิเสธ (พร้อมเหตุผล) |

## 6. กรณีปฏิเสธคำขอ

- แจ้งเหตุผลเป็นลายลักษณ์อักษรให้ผู้ร้องขอทราบ (เช่น พิสูจน์ตัวตนไม่ได้, มีหน้าที่ตามกฎหมายให้เก็บข้อมูลไว้)
- แจ้งสิทธิของผู้ร้องขอในการร้องเรียนต่อสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) — ดูข้อ 7

## 7. การร้องเรียน

หากผู้ร้องขอไม่พอใจผลการดำเนินการ มีสิทธิร้องเรียนต่อสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล
(สคส.) — ช่องทาง: `[ระบุช่องทางร้องเรียนปัจจุบันของ สคส. ให้ DPO ตรวจสอบก่อนเผยแพร่]`

## หมายเหตุการนำไปใช้ (สำหรับ dev)

- เอกสารนี้ปิด checkbox `ขั้นตอนใช้สิทธิเจ้าของข้อมูล (DPIA ข้อ 7)` ใน [`GO-LIVE.md`](./GO-LIVE.md) ข้อ 3
  เมื่อ DPO + ที่ปรึกษากฎหมายรับรองแล้ว
- การลบ/ทำลายข้อมูล (ข้อ 4) ยังเป็นกระบวนการที่ทำโดยผู้ดูแลระบบด้วยมือ — ยังไม่มี admin UI
  สำหรับ DPO สั่งลบเอง; ถ้าปริมาณคำขอมากขึ้นในอนาคต ควรพิจารณาทำ endpoint เฉพาะสำหรับ DPO
- ควรพิจารณาเปิด access log การเข้าถึงผล KYC ให้ครบก่อน (R5 ใน `DPIA.md`) เพื่อให้ DPO ตรวจสอบ
  ได้ว่าใครเข้าถึงข้อมูลของผู้ร้องขอบ้างก่อนตอบคำขอเข้าถึง
